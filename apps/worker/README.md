# Cloudflare Worker adapter

This Worker maps `@bcd-embed/server` artifact reads to a local or deployed R2
binding. Successful bodies stream from R2. The server owns route validation,
bounded metadata/index parsing, error bodies, HTTP validators, and cache policy;
the Worker adds a named Cloudflare Cache API layer. Cache API entries expire at
their `max-age`. Cloudflare's Cache API does **not** implement
`stale-while-revalidate`; that directive remains on client-facing `current`
responses, but edge cache misses re-read R2 after one day. Cache API entries
are local to a data center and do not bypass Worker invocation.
Only canonical `current` routes and `meta.json` use this edge cache. Pinned
routes retain their public immutable cache headers, but bypass Cache API so a
retired snapshot cannot remain edge-served for a year after metadata removal.
Each pinned origin read rechecks membership and streams the artifact from R2;
consumer caches may retain a previously fetched immutable response.

`pnpm --filter @bcd-embed/worker test` builds a dry-run bundle and runs a
Miniflare/workerd integration suite against a local R2 binding seeded from an
actual generator-produced, Array-scale BCD snapshot. It never accesses a
Cloudflare account. `pnpm --filter @bcd-embed/worker wrangler:dry-run` validates
the deployable bundle without deploying. Run `pnpm check` from the repository
root before review.

`worker-configuration.d.ts` is generated by
`pnpm --filter @bcd-embed/worker wrangler:types`, and the typecheck fails when
it no longer matches what the pinned Wrangler generates. On Dependabot pull
requests, `.github/workflows/dependabot-worker-types.yml` regenerates it and
commits it to the pull request's branch. The commit was made with the
workflow's own token, so its CI run waits for someone with write access to
approve it. If the workflow fails, regenerate the file by hand:

1. Check out the Dependabot pull request's branch and run `pnpm install`.
2. Run `pnpm --filter @bcd-embed/worker wrangler:types`.
3. Run `pnpm --filter @bcd-embed/worker typecheck` to confirm the file matches.
4. Commit only `worker-configuration.d.ts` to that same branch, with
   `[dependabot skip]` in the message so Dependabot keeps rebasing the pull
   request.

The compatibility date is pinned to 2026-09-23 in `wrangler.jsonc` and in
`tests/worker.test.ts`. Wrangler and the standalone Miniflare that the
integration tests use each bundle their own workerd runtime, and a runtime
rejects a compatibility date later than its own release. Wrangler's runtime is
newer, so the limit is Miniflare's (version `5.20260923.0-alpha`, which bundles
the 2026-09-23 runtime). Upgrade Miniflare before advancing the date, then
change the date in both files together.

## Runtime behavior

The Worker serves offline variants with `encodeBody: "manual"`; no large-body
compression runs on requests. It restores `request.cf.clientAcceptEncoding`
before negotiation because Cloudflare rewrites the origin header. Cache keys
include the selected encoding and responses carry `Vary: Accept-Encoding`.

A stored Brotli or gzip copy has no `Content-Encoding` header. Its encoding is
kept in the private `x-bcd-cache-content-encoding` header, and a hit restores
`Content-Encoding` from it. On the deployed edge, a cached response stored with
`Content-Encoding` came back compressed a second time, under a weak ETag, which
a client cannot decode (observed in November 2026; Miniflare does not reproduce
it). A hit whose stored encoding does not match its cache key is discarded and
the request reads R2. The cache is named `bcd-embed-api-v2`, so entries stored
the old way under `bcd-embed-api-v1` are never read.
A private Cache API header preserves encoded length and is stripped on all
public responses. Cached GET uses `FixedLengthStream` when needed to retain
GET/HEAD wire length without buffering.

The Worker creates one tree cache per isolate, at module scope, and passes it to
the handler on every request. Requests that the same isolate serves then share
parsed roots and shards, so a warm request reads only `meta.json` and the blob.
The cache lives in memory only. It is not written to the Cache API, so a new
isolate starts cold and reads the root and shard once.

R2 objects require lowercase 64-digit `customMetadata.sha256`; wire ETags quote
this digest. Missing/malformed metadata fails closed; native `checksums.sha256`,
when available, must match. Uploads without a native checksum must establish
the digest through verified upload and byte readback before publication. The
hot path never hashes large stored bodies. Only small generated errors use
request-time compression, with a 16 KiB input bound.

Strict raw-HTTP local tests verify identity, Brotli, gzip, HEAD, 304, errors,
and exact encoded bytes. Tests check that a compressed entry is stored without
`Content-Encoding`, that a hit restores it, and that an entry stored any other
way is ignored.
This is local transport evidence, not deployed Cloudflare edge acceptance, so
run the endpoint verifier against the deployed Worker after every deploy:

```bash
node packages/server/scripts/verify-endpoint.mjs --base-url https://api.browser-compat.dev --allow-remote
```

The verifier requests the compressed feature twice and decodes both bodies. Each
must decode to the identity bytes, which catches a body compressed twice even
when its headers look right. Cloudflare rejects the `%ZZ` and `%00` probes
itself, with an HTML `400` and no CORS header, before the Worker runs; on a
remote target the verifier accepts that response for those two probes only.

Runtime errors emit structured, non-request-derived error classes to Workers
Logs and Sentry when the optional `SENTRY_DSN` Worker secret is configured.
The Sentry SDK is configured to drop request, user, breadcrumb, message, stack,
and extra fields; it receives only bounded error types and two fixed tags,
`component: worker` and `event: bcd_embed_worker_error`, which alert rules can
filter on. Without that secret,
Sentry is deliberately disabled and no alert delivery is implied. Configure and
test an alert before public launch.
